# 智能客服系统 PRD

## 背景与调研结论

公司内部 IT 与行政支持目前靠员工私下找对接人。夜间无人、找不到人，重复问题反复消耗对接人时间。

竞品调研（见 `docs/competitor-analysis.md`）后确认采用 **方案 D（融合）**：

- 场景与目标对齐飞书服务台：内部员工自助、AI 先拦重复问、转人工是为了找到人。
- 使用结构对齐智齿客服：员工咨询、坐席接待、知识维护三条工作台。
- 工单状态对齐 Jira Service Management 的简化版：AI 接待中 → 待处理 → 处理中 → 已完结。不引入 SLA、资产台账、服务目录。
- 回答方式采用已确认链路：标准问答高置信直接作答；否则意图识别（模糊则反问）；清晰则结合长期画像与最近 3 轮对话改写后再检索生成。员工侧答疑与坐席侧智能回答走同一条业务链路。

产品形态：独立 Web 系统，单组织，中文。

---

## 产品目标与成功结果

- 目标用户：公司内部员工（提问）与值班坐席（IT / 行政对接人）。
- 当前问题：对接靠找人；夜间无人；同一类问题反复问。
- 产品承诺：员工随时提问，常见问题由系统当场答完；答不了或必须人处理时，能转到坐席并带上完整上下文。
- MVP 成功结果：
  1. 员工能完成「提问 → 得到可用答复或被反问补信息」。
  2. 需要人时能转人工，坐席能回复并结单，员工能在同一条咨询里看到人工回复。
  3. 用 Markdown 更新制度/说明后，后续提问能用到这些材料。
- 明确不承诺：外部客户客服、多组织、即时通讯渠道接入、SLA、资产台账、满意度与运营报表。

## 用户角色与权限原则

MVP 使用同一套登录账号，登录后可进入员工咨询、坐席接待、知识维护三个工作台（与已确认的入口跳转一致）。角色表示用法，不是互斥账号类型。V2 再做分权。

| 角色 ID | 角色 | 目标 | 当前阻碍 | 允许做什么 | 不允许做什么 |
|---|---|---|---|---|---|
| R-001 | 员工 | 尽快得到 IT / 行政答案 | 找不到人、夜间无人 | 登录、提问、查看和续自己的咨询、转人工 | 查看他人咨询、结他人的工单、导出记录 |
| R-002 | 坐席 | 处理转来的问题并给出结论 | 信息不完整、重复回答 | 看待处理工单、接入、人工回复、使用智能回答、分类、结单 | 在已完结工单中继续发言、重新打开已完结工单 |
| R-003 | 知识维护者 | 让系统有材料可答 | 制度散落、无人整理 | 上传 Markdown、查看已入库文档、启用或停用文档 | 上传非 Markdown、对接外部网盘 |

权限原则：

- 员工只能看到自己发起的咨询。
- 坐席可看待处理、处理中的工单；未转人工的咨询不对坐席展示。
- 登录用户可查看知识库、上传 Markdown，并启用或停用文档。
- 登录后无需重新登录即可在员工咨询、坐席接待、知识维护三个工作台之间切换。
- 长期画像只用于改写提问，界面不展示，不提供手工编辑。
- MVP 不提供会话导出或下载。

## 核心业务场景与用户旅程

| 场景 ID | 场景 | 角色 | 触发条件 | 业务结果 |
|---|---|---|---|---|
| S-001 | 登录进入系统 | 内部用户 | 打开系统并登录 | 身份可识别 |
| S-002 | AI 答疑闭环 | 员工 | 提出 IT / 行政问题 | 得到直接答案、反问补细节、或基于知识的生成答复 |
| S-003 | 续聊历史 | 员工 | 打开自己的历史咨询 | 未完结可继续；已完结只能查看 |
| S-004 | 转人工 | 员工 | AI 不够或必须人处理 | 工单进入待处理，对话上下文保留 |
| S-005 | 坐席处理并回复 | 坐席 | 从待处理列表接入 | 员工侧看到人工回复；工单为处理中 |
| S-006 | 坐席智能回答 | 坐席 | 需要参考知识再回复 | 得到与员工答疑同一套逻辑的建议答复，由坐席决定是否发出 |
| S-007 | 分类与结单 | 坐席 | 问题已处理完 | 工单带分类并变为已完结；双方不能再发消息 |
| S-008 | 知识更新 | 知识维护者 | 上传制度 / FAQ 的 Markdown | 文档入库；默认可用于后续提问 |
| S-009 | 三端工作台切换 | 内部用户 | 已登录 | 在员工咨询、坐席接待、知识维护之间切换且保持登录 |
| S-010 | 启停知识文档 | 知识维护者 | 已有入库文档 | 启用后参与答疑；停用后不再被检索或直接作答 |

### 主旅程（跨角色）

1. 内部用户登录，可进入并在员工咨询、坐席接待、知识维护三个工作台之间切换。
2. 员工提出问题，系统形成一条咨询工单，状态为 AI 接待中。
3. 系统先做标准问答高置信匹配：达到约定阈值则直接作答；未达到则判断意图。意图模糊则只反问；意图清晰则结合该账号长期画像和当前工单最近 3 轮对话改写提问，再检索知识并生成答复。
4. 员工得到可用答复则本轮停留在 AI 接待中；需要人时主动转人工，工单变为待处理。
5. 坐席在接待工作台看到该工单，选择接入后变为处理中；可直接人工回复，或先取智能回答建议再发出。接入后系统不再对该工单自动对外发言。
6. 坐席分类并结单，工单变为已完结。员工在自己的历史中可看到全程（含人工回复），但不能再发言。
7. 知识维护者上传 Markdown，入库成功后默认启用，新的提问可以使用这些材料；可随时停用或重新启用某篇文档。停用后的材料不再参与答疑。

## MVP 范围、V2+ 与非目标

### MVP 范围

| 场景 | MVP 必须成立的业务结果 | 深度边界 | 延后内容 |
|---|---|---|---|
| S-001 | 用账号登录后使用系统 | 单组织、本地账号 | SSO、多组织 |
| S-002 | 员工提问后能得到 AI 答复或反问 | 中文；一条答疑链路；只使用启用中的知识 | 多语言、多机器人 |
| S-003 | 只能续自己的未完结咨询 | 已完结只读 | 重新打开工单 |
| S-004 | 转人工后坐席能看到完整对话 | 不按技能组派单，坐席自选 | 技能组、排队、询前表 |
| S-005 | 坐席回复同步到该员工的同一条咨询 | 一对一工单 | 转交其他坐席 |
| S-006 | 坐席可拿到建议答复再发送 | 建议默认不自动发出 | 自动发送、个人话术库 |
| S-007 | 分类 + 结单后不可再发言 | 分类为业务标签 | 报表、质检 |
| S-008 | 仅 Markdown 入库后可用于回答 | 单库、登录用户可上传可看 | 权限目录、其他文件格式、版本回滚 |
| S-009 | 登录后可在三个工作台之间切换 | 同一登录会话内切换，不做分权拦截 | 按角色隐藏入口 |
| S-010 | 可启用或停用已入库文档 | 按整篇文档启停，不做切片级启停 | 定时下架、版本回滚 |

### 版本规划

#### MVP

| 场景 | 必须达到的结果 | 纳入理由 |
|---|---|---|
| S-001 | 登录后身份可识别 | 使用前提 |
| S-002 | 夜间 / 无人时也能得到 AI 答复或被反问 | 核心痛点 |
| S-003 | 能续聊，已完结不能发 | 服务连续性 |
| S-004～S-007 | 找不到人或 AI 不够时能找到坐席并结案 | 核心痛点 |
| S-008 | 知识可更新，回答能跟上制度 | 答疑有材料 |
| S-009 | 同一账号可在三端之间切换 | 员工、坐席、知识维护共用账号 |
| S-010 | 错误或过期知识可停用而不必删除 | 避免过期制度继续被回答 |

#### V2+

| 结果 | 延后理由 | 前置依赖 |
|---|---|---|
| 员工 / 坐席 / 知识管理员分权 | 先保证三条工作台能跑通 | 组织与权限方案 |
| 按 IT / 行政技能组派单 | 当前痛点是找不到人，先集中一个坐席台 | 分组与值班 |
| 重新打开已完结工单 | 避免状态混乱 | 结单规则稳定 |
| 企微 / 飞书入口 | 先独立 Web 闭环 | 渠道适配 |
| 报表与满意度 | 不解决当前找不到人 | 工单数据稳定 |
| 多格式知识与权限目录 | 先把 Markdown 入库跑通 | 解析与权限模型 |

### 非目标

- 外部客户服务、多渠道（邮件 / 企微 / 飞书）、多组织、多语言。
- 角色分权、技能组派单、排队、转交、重新打开已完结工单。
- SLA、资产台账、服务目录、满意度、质检、运营报表。
- 会话导出、界面编辑长期画像、非 Markdown 知识、外部网盘同步。

## 业务规则

| 规则 ID | 规则 | 适用场景 | 违反时结果 |
|---|---|---|---|
| BR-001 | 员工一开口提问就形成一条咨询工单，初始为「AI 接待中」 | S-002 | 不允许存在无工单的对话 |
| BR-002 | 标准问答相似度达到约定阈值（0.8）时直接给出该答案，不再走反问与生成 | S-002 | 未达到则进入意图识别 |
| BR-003 | 意图判定为模糊时，只允许反问补信息，不得直接生成知识答案 | S-002 | 改为反问，等待员工补充 |
| BR-004 | 改写提问时必须带上该账号长期画像，以及当前工单最近 3 轮对话；不足 3 轮有多少用多少 | S-002 / S-006 | 禁止再拼入约定以外的全量历史 |
| BR-005 | 长期画像由每轮对话按规则抽取后写在该账号上，只用于改写；界面不展示、不提供手工编辑 | S-002 | 忽略手工改画像的请求 |
| BR-006 | 只有员工主动转人工后，工单才进入「待处理」，坐席才能在列表中看到 | S-004 | 未转人工的咨询不对坐席展示 |
| BR-007 | 坐席选择接入后工单变为「处理中」，此后由人工回复；系统不再对该工单自动对外发言 | S-005 | 拒绝再自动生成对外消息 |
| BR-008 | 坐席智能回答只产生建议，发出前必须由坐席确认 | S-006 | 建议不得直接出现在员工会话里 |
| BR-009 | 已完结工单禁止任何人再发送消息 | S-003 / S-007 | 拒绝发送并提示已完结 |
| BR-010 | 已完结工单不可重新打开；员工需新开咨询 | S-003 | 拒绝恢复发送 |
| BR-011 | 员工只能看到自己的咨询；坐席可看待处理与处理中工单 | S-003 / S-005 | 对不可见工单视为不存在 |
| BR-012 | 知识只接受 Markdown；其他格式拒绝入库 | S-008 | 提示仅支持 Markdown |
| BR-013 | MVP 不提供会话导出或下载 | 全部 | 只提供在系统内查看 |
| BR-014 | 登录后无需重新登录，即可在员工咨询、坐席接待、知识维护三个工作台之间切换 | S-009 | 拒绝切换或要求重新登录均视为失败 |
| BR-015 | 知识文档入库后默认启用 | S-008 | 新入库文档必须可被答疑使用，除非随即被停用 |
| BR-016 | 仅「启用中」的知识可参与标准问答匹配与检索生成；停用后立即对后续提问生效，不删除文档 | S-002 / S-006 / S-010 | 停用文档不得再被直接作答或检索引用 |

工单状态语言：**AI 接待中 → 待处理 → 处理中 → 已完结**。

答疑路径语言（员工答疑与坐席智能回答共用）：

1. 标准问答高置信匹配，达到阈值则直接作答。
2. 否则做意图识别：模糊则反问；清晰则进入改写。
3. 结合长期画像与最近 3 轮对话改写提问。
4. 对改写后的提问做语义检索与关键词检索，混合排序后再生成答复。上述匹配与检索只使用启用中的知识。

## 业务数据概念与生命周期语言

| 概念 | 业务含义 | 由谁产生 | 生命周期 |
|---|---|---|---|
| 账号 | 登录身份；挂长期画像 | 使用者被发放或自行注册 | 有效（MVP 不做停用流程） |
| 咨询工单 | 一次提问服务的全过程 | 员工首条提问时产生 | AI 接待中 → 待处理 → 处理中 → 已完结 |
| 消息 | 员工、系统或坐席在工单里的一句内容 | 各角色或系统 | 随工单保存，MVP 不可删除 |
| 工单分类 | 坐席给工单打的业务标签 | 坐席 | 可改到结单为止 |
| 知识文档 | 一篇 Markdown 制度或说明 | 知识维护者上传 | 已上传 → 已入库且启用 / 已入库且停用（入库失败则未生效） |
| 知识切片 | 文档切出的检索片段 | 入库过程 | 随文档存在 |
| 标准问答 | 用于高置信直接作答的问答对，来自入库知识 | 入库过程 | 随知识可用 |
| 长期画像 | 账号上少量稳定属性，供改写提问 | 每轮规则抽取 | 随账号更新 |
| 短期记忆 | 当前工单最近 3 轮问答 | 对话过程 | 随新轮次滑动 |

## 风险与约束

- 同一账号能进坐席台和知识库：存在误结单或上传错误制度的可能。MVP 接受，V2 分权。
- 知识为空时，系统无法给出有依据的知识答复，只能反问或无法有效作答。上线前必须先有一批 Markdown。
- 大模型或向量化不可用时，夜间自动答疑中断。
- 高置信阈值或意图判断不准时，可能该直出的去生成，或该反问的直接作答。
- 转人工后若无坐席在线，工单停在待处理。产品允许，员工侧需明确「已提交，等待对接人」。
- 知识、画像、工单与消息保存在本系统内，不依赖外部云知识库。

约束：物理表字段、接口 DTO 与实施任务分别见 `docs/data-model.md`、`docs/api-contracts.md`、各 Feature `plan.md`。选型与 config 键以 `docs/tech-spec.md` 为权威。
