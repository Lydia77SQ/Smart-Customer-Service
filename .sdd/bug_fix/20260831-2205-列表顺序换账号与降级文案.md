# Bug 修复报告：知识列表顺序、降级文案、未生效清理、换账号清空咨询

## 用户原话

> 1、知识库文档顺序固定不要动；2、优化找不到答案的文案为“很抱歉，您的问题我暂时无法解答，请转人工等待对接人接入”；3、清除掉历史未生效的知识库文档；4、另一账号登录后，员工咨询页需要清空，不展示上一个账号的问答对话；5、请生成一份企业内部it知识库文档，我要测试上传

## 经验回查

- 是否已有相关经验：有相近
- 相关经验：
  - 上一条 Bugfix：启停后列表按 `updated_at` 重排，会放大开关连动
  - T-017：员工列表按 `requester_id` 隔离，但前端 Pinia 未在换账号时清空 `detail`
- 为什么仍然犯错：排序用了会被启停改写的字段；会话清理只清 token，不清工单 store

## 问题分析

- 现象：
  1. 启停后知识列表行会跳动
  2. 找不到答案的提示不够明确
  3. 列表里留有历史未生效文档
  4. 换账号后员工页仍可能显示上一账号对话
- 影响范围：知识列表、答疑降级文案、运行时知识库脏数据、员工咨询页 Pinia
- 直接原因：
  1. `list_page` 按 `updated_at DESC` 排序
  2. `DEGRADED_QA_MESSAGE` 旧默认文案
  3. 历史 `failed`/`processing` 行未清理
  4. 登录/退出未 `$reset` 工单 store，员工页 `onMounted` 未先清空再拉 `GET /mine`
- 根本原因：列表顺序应与启停无关；工作台内存状态必须跟随当前登录账号

## 修复方案

- 修改文件：见完成说明
- 修改说明：
  - 知识列表改为 `created_at ASC, id ASC`
  - 降级文案改为用户指定句，并同步 `.env.example` / 配置默认值
  - 运行时库删除 7 条 failed/processing 文档及对应切片、问答、原文
  - 退出登录、重新登录、进入员工页时重置工单/坐席/知识 store
  - 新增测试用 Markdown：`samples/企业内部IT知识库.md`
