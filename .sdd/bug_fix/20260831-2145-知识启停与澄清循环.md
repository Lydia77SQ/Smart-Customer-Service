# Bug 修复报告：知识开关连动与澄清循环

## 用户原话

> 发现bug请修复：1、启用第二个知识库文档时，第一个可能会自动关闭；2、意图澄清后找不到答案还会一直重复问，找不到答案就说不知道，转人工

## 经验回查

- 是否已有相关经验：有相近、无同一缺陷
- 相关经验：
  - T-015：PATCH 只改当前文档 `status`，停用不删切片；未写「多文档可同时 enabled」
  - T-016：意图模糊只反问；未限制反问次数，未把上一轮 `last_result_type` 纳入分类
- 为什么仍然犯错：启停任务只测单篇；答疑任务把每次提问当成独立短句，澄清后的补充仍走 ambiguous

## 问题分析

- 现象：
  1. 知识列表打开第二篇时，第一篇开关/状态可能变成停用
  2. 系统反问后员工补充细节，仍反复反问，不告知无法作答、不提示转人工
- 影响范围：F-013 知识维护工作台；F-004 员工答疑（F-009 共用 QaPipeline）
- 直接原因：
  1. 开关用原生 `change` + 列表按 `updated_at` 重排，行复用时可能把错误 `checked` 打到另一篇
  2. 意图分类只看当前句；画像虽写入 `last_result_type` 但流水线未读取；无知识时仍让模型生成
- 根本原因：
  1. 多文档独立启停缺少前端隔离与回归用例
  2. 澄清是一次性补信息，不是无限追问；无知识应收口为降级文案（含转人工），不自动调用转人工 API

## 修复方案

- 修改文件：
  - `frontend/src/pages/KnowledgePage.vue`
  - `backend/src/services/knowledge.py`
  - `backend/src/services/qa_pipeline.py`
  - `backend/tests/features/f013/test_toggle.py`
  - `backend/tests/features/f004/test_clarify.py`
  - `backend/tests/features/f004/test_ask.py`
- 修改说明：
  - 每行开关独立 `id`/`name`；按该行当前 status 计算下一态，`click.prevent` 避免列表刷新误触发其它行
  - PATCH 只更新目标文档，测试：启用第二篇后第一篇仍为 enabled
  - 上一轮为 clarification 且本轮仍 ambiguous → `degraded`（`DEGRADED_QA_MESSAGE`，提示转人工，不自动转单）
  - 意图分类带最近对话；检索无片段不再生成，直接降级

  3. 员工提问被反问后回复短补充；若仍无匹配，应出现「暂时无法自动答疑…或转人工」，而不是同一句反问；点「转人工」仍由员工操作
